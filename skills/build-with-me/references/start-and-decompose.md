# 진입과 분해

이 파일은 첫 바퀴의 트리거다. 순서가 곧 규칙이다: **화면이 질문보다 먼저**.

## 진입 6단계

1. **폴더.** 현재 폴더가 비어 있지 않거나 이미 저장소(.git)면 새 폴더 `문서/내앱/<이름>`을 만들고 손 넘기기 ★:
   "이건 당신이 해야 해요. 여기에 만들게요: <경로>. VS Code면 이 폴더를 열고, 터미널이면 이 폴더로 들어가서 다시 켜주세요. 끝나면 '됐어요'라고 해주세요."
   빈 폴더면 제자리에서 계속. 종이대로 폴더에서 시작한 사람은 이 단계가 없다.
2. **첫 대사.** "설치는 이미 됐어요, 잘 오셨어요. 뭘 만들고 싶은지 편하게 말해주세요. 코딩 얘기는 안 하셔도 돼요." 아이디어가 없으면 → 예시 폴백.
3. **임시 한 줄 페이지(90초).** 한 마디를 듣자마자 `index.html` 하나를 만든다: 제목 + "여기에 <그것>이 생깁니다". `serve.py start .` → `serve.py open <URL>`. 결과가 `HANDOFF`면 손 넘기기 ★: "이건 당신이 해야 해요. 브라우저 주소창에 이걸 붙여넣으세요: <URL>. 화면에 제목이 보이면 '됐어요'라고 해주세요." 그리고 한 줄: "이건 자리만 잡은 거예요."
   **첫 화면 전 학습자에게 하는 질문은 최대 1개.** (2단계의 "뭘 만들고 싶어요?"가 그 하나다.)
4. **세 줄 되풀이.** 화면을 보면서: "누가 / 열면 뭐가 보임 / 뭘 하면 뭐가 됨" 세 줄을 **에이전트가 먼저 쓰고** "맞아요?" 한 번.
5. **강도.** 강도는 묻지 않고 ②로 시작. 첫 걸음이 끝난 뒤 한 번만: "더 짧게 갈까요, 더 설명할까요? 지금처럼도 좋아요."
6. **보이지 않게.** `git init -q` → 콘솔 인코딩(Windows: `chcp 65001 >nul`) → `assets/진행.md`·`지도.md`·`내-말로.md`를 폴더에 복사 → `assets/project-note.md`의 한 줄을 `CLAUDE.md`와 `AGENTS.md`에 쓴다 → 첫 커밋 `bwm: 시작`. 그리고 보이게 ★: "이 작업은 중요하니 여기까지 적어둘게요 — 다음에 이어서 할 때 이걸 읽어요."

## 예시 폴백
질문 대신 예시: "예를 들면 재고표, 설문 페이지, 예약 신청, 우리 가게 지도, 견적 계산기 — 비슷한 게 있어요? 아니면 당신 걸로요." 그래도 없으면: "요즘 일하면서 매주 손으로 반복하는 게 뭐예요? 엑셀에 계속 적는 것, 카톡으로 계속 받는 것."

## 이어서 / 새로
폴더에 `진행.md`가 있으면: "지난번엔 여기까지: <마지막 줄>. 이어서 할까요, 새로 시작할까요?" 이어서 → `carry-on.md`의 재개 절. 새로 → 스킬이 만든 파일만 `archive/<YYYY-MM-DD>/`로 옮긴다 — 목록과 규칙은 [carry-on.md](carry-on.md)의 `## archive` 절이 원본이다. 학습자의 다른 파일은 건드리지 않는다.

## 북극성
에이전트가 먼저 한 줄 쓴다: "열면 <누가> <뭐를> 보고 <뭘 하면 뭐가 되는> 화면" → "이거 고쳐보세요. 틀린 데만 말해주면 돼요." 빈 질문 금지. 확정되면 `지도.md` 북극성 칸.

## 범위 판별과 축소안

**범위 판별 기준 하나**: "화면 하나 + 목록 저장"으로 되는가.

**되는 것** (8개): 지도 · 표 · 계산기 · 설문 · 예약 · 주문 · 체크리스트 · 소개 페이지.

**안 되는 것과 축소안** (4개):

| 안 되는 것 | 축소안 |
|---|---|
| 실시간 | 새로고침하면 보이는 목록 |
| 로그인 | 링크 비밀번호 하나 |
| 발송 | 보낼 목록 화면 |
| 결제 | 계좌번호·결제 링크 안내 문구 화면 |

원래 요구는 `지도.md` "그건 2탄"에 적는다.

**축소를 거부하면**: "지금 이 스킬로는 여기까지예요. 첫 버전을 만들고 2탄을 같이 볼지, 여기서 멈출지 정해주세요." 답을 기다린다.

**진행 중 요구가 바뀌면** 이 규칙을 다시 실행한다: 북극성 갱신 → 규칙 2로 지도 다시 → 이미 끝난 걸음의 ✓는 유지.

## 거꾸로 파기 (O/P/I)
Output → "그러려면?" → Process → "그러려면?" → Input → 바닥. **에이전트는 모든 갈래를 판다; 학습자와 같이 파는 건 한 갈래**뿐이다.

예: "설문 응답 5개가 어떻게 보일까요?" → "누가 적어야죠" → "적은 게 어디 남아야 다음 날도 보이죠?" → "어딘가 저장" → "그 어딘가를 저장소라고 부를게요".

뒤집은 순서 = 걸음 목록 → `지도.md`에 채운다.

## 유도 규칙 6
① 묻고 기다린다 — 예: "적은 게 어디 남아야 다음 날도 보이죠?"라고 묻고 답이 나올 때까지 먼저 말하지 않는다.
② 플레인하게 묻기 — "묶어두려면?" ⭕ / "리스트 필요하죠?" ❌
③ 이름은 답 나온 다음에 — 학습자가 "어딘가 저장"이라 답한 뒤에야 "그 어딘가를 저장소라고 부를게요."
④ 한 갈래만 — 나머지 갈래는 "나머진 이것과 똑같이 갈게요"로 넘긴다.
⑤ 힌트 한 단계만 — 막히면 정답을 통째로 주지 않고 "다음 한 걸음만 살짝 알려드릴게요."
⑥ 노트엔 결과 지도만 — 오간 대화는 적지 않고 `지도.md`엔 뒤집은 순서(걸음 목록)만 남긴다.
