# 공개 직전

## 순서
**호스팅 계정 → 네 질문 → 배포 → 링크.** 네 질문을 통과하기 전에는 공개 주소가 생기지 않는다. 첫 공개는 네 질문 전부, 재배포는 한 줄.

## 손 넘기기 세 번
① GitHub 계정 ★: "이건 당신이 해야 해요. 화면에 **Sign up**이 보이면 **이메일로 가입**을 누르세요. 메일이 오면 **인증 링크**를 누르세요. 끝나면 '됐어요'라고 해주세요."
② gh 설치 ★: 에이전트가 먼저 `winget install GitHub.cli`를 직접 실행한다; 실패하면 — "이건 당신이 해야 해요. 화면에 **터미널**이 보이면 아래 한 줄을 붙여넣고 **엔터**를 누르세요: `winget install GitHub.cli`. 끝나면 '됐어요'라고 해주세요."
③ 로그인 ★: 에이전트가 `gh auth login -h github.com -s repo,delete_repo -w`를 실행하고 — "이건 당신이 해야 해요. 화면에 **여덟 글자 코드**가 보이면 그걸 복사해서, 열린 브라우저에 붙여넣고 **Authorize**를 누르세요. 끝나면 '됐어요'라고 해주세요." (`delete_repo`를 지금 같이 받아야 "내리기"가 한 번에 된다.)
'됐어요'가 5분 안에 안 오거나 "안 돼요"면 → '안 돼요' 프로토콜(`carry-on.md`). 같은 곳에서 두 번 막히면 `지도.md` "막힌 곳" + 종결 경로.

## 네 질문
① **누가 볼 수 있나** — "이 링크는 아는 사람 누구나 열 수 있어요. 저장된 것은 <규칙 문장>이에요." 저장소가 있으면 `guard.py probe` 결과를 붙인다: "방금 확인해보니 밖에서는 적기만 되고 보기·지우기는 막혀요." 받는 데이터에 이름·연락처가 있으면 볼 수 있는 사람은 당신 하나로 잠근다(probe로 확인).
② **비밀키가 밖에 나가나** — `guard.py pre-share .` 결과를 그대로: "공개해도 되는 파일들이에요" / 경고 줄.
③ **비용이 무한인가** — "누가 만 번 눌러도 돈이 안 나가요. 무료 저장소는 한도에 닿으면 멈출 뿐 청구되지 않아요." (a) 저장소 없음 → 통과. (b) 저장소 있음 → 무료 요금제인지 한 줄 확인.
④ **되돌릴 수 있나** — "내리는 법은 한 줄이에요: '내려줘'라고 하면 제가 내려요. 내리면 3분쯤 뒤에 주소가 사라져요."
네 개 다 "맞아요"를 받은 뒤에만 아래로.

## 배포 한 줄
```bash
ACCOUNT=$(gh api user --jq .login)
gh repo create <이름> --public --source=. --push
gh api -X POST "repos/$ACCOUNT/<이름>/pages" -f "source[branch]=main" -f "source[path]=/"
```
링크 `https://$ACCOUNT.github.io/<이름>/`. 첫 200까지 약 1분(실측 43초) — "1분쯤 걸려요. 됐는지 제가 확인할게요" → 200이면 열어준다(`serve.py open`이 아니라 공개 주소를). 그리고 보이게 ★ 기록.

## 배포 실패 경로
에이전트가 먼저 **조용히 한 번 재시도** → 그래도 실패하면 에러 번역 세 줄(무슨 일 / 왜 / 뭘 할지):
- `Bad credentials` / `Authentication failed` → "로그인이 풀렸어요 / 열쇠가 오래되면 그래요 / 다시 로그인할게요" → 손 넘기기 ③
- `command not found` → "도구가 없어요 / 아직 설치가 안 됐어요 / 설치할게요" → 손 넘기기 ②
- `Name already exists on this account` → 질문 없이 이름 뒤에 날짜를 붙여 재시도: `gh repo create <이름>-$(date +%Y%m%d) --public --source=. --push`
- 그 외 두 번 실패 → 종결 경로: "오늘은 내 컴퓨터에서 되는 버전까지 마무리할게요. 링크는 다음에 다시 해봐요" + `진행.md`에 재시도 지점 + "막히면 `진행.md`와 `지도.md`를 강사(또는 동료)에게 보내세요."

## 재배포 한 줄
"바뀐 것이 네 질문에 닿나요?" — 저장 규칙·키·비용에 닿지 않으면 한 줄로 통과하고 `git push`. 닿으면 그 질문만 다시. 저장소가 있으면 `probe`를 다시 돌린다. 링크 확인은 배포 때 정한 `$ACCOUNT`를 그대로 쓴다.

## 내리는 법
`gh repo delete "$ACCOUNT/<이름>" --yes` (delete_repo 스코프; `$ACCOUNT`는 배포 때와 같은 `gh api user --jq .login` 값). 403이면 `gh repo edit --visibility private --accept-visibility-change-consequences` + Pages 해제. 어느 쪽이든 주소는 약 3분 뒤 404.

## (선택) 한 번 더 보기
fresh-eyes-check가 설치되어 있으면 네 질문 뒤에: "남에게 보여주기 전에, 이 대화를 모르는 다른 모델이 화면을 한 번 봐요." — `Use fresh-eyes-check before you decide this.`를 호출하고 결과를 한 줄로. 없으면 조용히 건너뛴다.
