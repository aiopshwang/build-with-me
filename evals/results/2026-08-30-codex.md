## 스파이크에서 한 일과 증거

환경: `codex-cli 0.150.0`, Windows, Git Bash. 작업 디렉터리는 `/c/tmp/bwm-codex-spike`
(레포 바깥, 커밋 대상 아님).

1. `codex login status` → `Logged in using ChatGPT` (로그인된 것처럼 보임).
2. `codex exec --json --skip-git-repo-check -C /c/tmp/bwm-codex-spike "안녕, 한 줄만 답해줘"`
   실행 → 종료 코드 1. stdout(JSONL) 전체:

   ```json
   {"type":"thread.started","thread_id":"01a051cf-0ba4-7b42-bd76-f91d1ff819bc"}
   {"type":"turn.started"}
   {"type":"error","message":"Your access token could not be refreshed because your refresh token was revoked. Please log out and sign in again."}
   {"type":"turn.failed","error":{"message":"Your access token could not be refreshed because your refresh token was revoked. Please log out and sign in again."}}
   ```

   stderr에는 `codex_models_manager`·`codex_login::auth::manager`가 ChatGPT 백엔드에
   `401 Unauthorized` / `token_invalidated` / `refresh_token_invalidated`로 응답한
   기록이 여러 줄 있었다.
3. 동일 명령을 stdin을 `/dev/null`로 명시해 재시도(우연한 네트워크 오류가 아닌지 확인) →
   같은 세 이벤트(`thread.started` → `turn.started` → `error`/`turn.failed`), 같은
   메시지. 일시적 문제가 아니라 재현되는 인증 실패.
4. `codex login --help`로 비대화형 재인증 경로를 확인했다 — `--with-api-key` /
   `--with-access-token` / `--device-auth`가 있으나, 셋 다 이 작업 환경(비대화형 서브에이전트,
   브라우저 없음)에서 사용자 본인의 자격 증명이나 브라우저 완료가 필요하다. 이 세션은
   비대화형이라 OAuth/디바이스 인증 흐름을 완료할 수 없고, 사용자에게 인증 코드나 토큰을
   요청하는 것도 규칙상 금지되어 있어 시도하지 않았다.

## 확인하지 못한 것 (원래 스파이크 체크리스트)

- JSONL 이벤트 타입 목록과 최종 assistant 메시지가 어느 이벤트에 실리는지 — 미확인
  (터미널 이벤트가 `error`/`turn.failed`뿐이었음).
- `codex exec resume --last --json`이 실제로 이전 세션을 이어가는지 — 미확인(첫 턴부터
  실패해 이어갈 세션이 없었음).
- 스킬 로드를 나타내는 이벤트가 있는지 — 미확인.
